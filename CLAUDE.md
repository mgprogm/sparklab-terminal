## What this is

A web terminal whose defining property is that **jobs survive the browser and the gateway**. Closing the tab, losing the network, or restarting the Node gateway must never kill a running process. `docs/DESIGN-SYSTEM.md` is the authoritative design and rationale — read it before making architectural changes.

It also ships an **Agent Chat**: a floating panel (bottom-right of the terminal) where an AI agent — a custom tool-calling loop over Azure OpenAI (`gpt-5.6-sol`), running as a separate `apps/agent-service` — can read any session's screen, type into it _with per-write approval_, create sessions through the gateway, operate an isolated Browser Use instance, and save a one-time-approved viewport capture through the selected terminal's gateway. See `docs/AGENT-PROTOCOL.md` and `docs/VIRTUAL-BROWSER.md`.

## Architecture: three independent lifetimes

The core idea is that the process owner is **tmux**, not the gateway and not the browser. Three layers fail independently:

```
Browser (xterm.js)  --WebSocket-->  Gateway (node-pty)  --tmux attach-->  tmux server --> shell + jobs
```

- **The gateway never owns the job.** On WS attach it spawns a node-pty running `tmux attach-session -t <name>`. On WS close it kills **only that pty** (which detaches the tmux client). It must **never** run `tmux kill-session` on disconnect — that line's absence is what keeps jobs alive. See `teardown()` in `src/server.js`.
- **tmux is the source of truth for session state.** There is no database. A restarted gateway rediscovers everything via `tmux has-session` / `tmux ls`. Sessions are created explicitly via `POST /api/sessions`; attach never creates.
- **The agent is a fourth, independent lifetime.** `apps/agent-service` runs the AI loop and can crash/restart without touching any pty. It is deliberately _not_ in the gateway (which stays plain-JS and dependency-minimal). It operates terminals **only** as a gateway REST client — never tmux directly — so the gateway stays the single enforcement point for the `web-` prefix and auth. The kill of a USER `web-` session still happens in **exactly one place** (the `DELETE /api/sessions/:id` handler); the agentic run engine additionally kills only its own `agrun-`-prefixed run sessions (via `tmuxKill()`, which is hard-constrained to `agrun-` names) and never a `web-` session. It reads via `GET /api/sessions/:id/screen` and writes via `POST /api/sessions/:id/keys` (both added for this; see `docs/TERMINAL-PROTOCOL.md`). The human keystroke path is untouched.
- **Browser processes are transient children of an agent loop.** `BrowserRuntime` lazily starts one local `uv run browser-use --mcp` subprocess per chat, with its own temporary profile and enforcing proxy. Stop, disconnect, and service shutdown must terminate the process group and remove temporary state. This lifetime must never become coupled to tmux or the gateway.
- **tmux's attach redraw is the single painter of the visible screen.** On attach, tmux redraws the current screen automatically (including full-screen apps like vim/htop). Scrollback history is additionally fetched via the REST `capture-pane` endpoint (`GET /api/sessions/:id/scrollback`) and injected client-side _behind_ the redraw on the first binary frame — see `docs/TERMINAL-PROTOCOL.md`. Naive replay ON TOP of the redraw remains forbidden (double-draw).

## Load-bearing invariants (don't break these)

- **Raw bytes end to end.** The pty is spawned with `encoding: null` so `onData` yields Buffers, never decoded strings. pty output → WS **binary** frames → `term.write(Uint8Array)`; keystrokes → `TextEncoder` → WS binary → `pty.write`. Decoding to a JS string anywhere mid-pipeline corrupts multibyte UTF-8 (verified with Thai input). Keep binary frames binary.
- **WS message routing is by frame type, not content.** Binary frame = keystrokes. Text frame = JSON control message (`resize`, `ping`). Server → client control messages are also JSON text (`exit`, `pong`). Anything new on the wire follows this split.
- **Reconnect resets the terminal before the redraw.** The client (`apps/terminal/src/features/terminal/connection.ts`) sets `freshConnect = true` on each (re)connect and calls `term.reset()` on the first binary frame after, so tmux's attach redraw doesn't stack on stale content.
- **Multi-viewer sizing:** sessions are configured with `window-size latest` + `aggressive-resize on` so tmux follows the most recently active client instead of shrinking to the smallest.
- **Multi-window: `layout.mode === "single"` is byte-identical to the pre-feature single-pane subtree.** `components/terminal-pane.tsx` returns a bare fragment (no chrome, no wrapper, no `data-*`) in single mode — this is what keeps every E2E gate + `strictmode-check` valid without opt-in. Each pane owns one ordinary `XTermComponent`, hence one `Connection`; `connection.ts`'s "exactly ONE connection is live" note is per-component, not global. `activeSessionId` is a sync-on-write mirror of the focused pane — never write it as anything else. A divider drag must not stream `resize` frames (rAF-throttle `fit()`, flush `sendResize()` on `pointerup` — the `resizeCoalesced` prop). See `docs/MULTI-WINDOW-DECISIONS.md`.

## Virtual browser invariants

- Read `docs/VIRTUAL-BROWSER.md` before changing browser code. The backend ownership chain is `agent-loop.ts` → `browser-runtime.ts` → local Browser Use MCP; `browser-proxy.ts` and `browser-security.ts` enforce public HTTP(S)-only egress.
- The model receives `browser_observe`, `browser_list_tabs`, structured `browser_act`, one-time-approved `browser_capture`, and the explicit handoff tool. Never add persistent browser approval, raw MCP, CDP, JavaScript, or general file/upload/download access.
- Browser screenshots and state are ephemeral in chat. The only filesystem seam is `browser_capture`: write the already-bounded viewport through the selected terminal session's gateway `fs/upload` route to an explicit absolute path. Persist only sanitized tool history—never image bytes or saved-path results; redact typed text and strip URL query strings/fragments.
- Frontend browser state lives separately in `features/browser-view/`. Preserve monotonically increasing revisions and close tombstones so a late frame cannot reopen a closed view. The overlay stays read-only, leaves xterm mounted, and moves focus away from xterm's hidden textarea.
- Browser setup is `uv sync` plus `uvx browser-use install` in the checkout, then `BROWSER_USE_PROJECT=/home/sparklab/workspaces/sparklab/browser-use` in `apps/agent-service/.env`. The initial `about:blank` observation intentionally emits no view.

## Frontend UI conventions

- **`DESIGN.md` (repo root) is the visual source of truth.** When creating or editing any frontend UI, base colors, typography, spacing, and component geometry on it (Warp-inspired language: warm near-charcoal canvas `#2b2622`, ink `#f7f5f0`, Inter type, understated CTAs, tight shape geometry). Prefer the existing Tailwind theme tokens (`bg-background`, `text-muted-foreground`, `border-border`, `bg-accent`, `text-chart-1`, …) which encode that palette — do not hardcode hex values that bypass them.
- **Icons: `lucide-react` is the default icon library.** Use it for all new icons (typical inline size here is `size-3.5`/`size-4`); don't introduce another icon set or inline ad-hoc SVGs.
- Reusable primitives live in `@sparklab/ui` (shadcn-style: `Button`, `Tooltip`, `Dialog`, `Separator`, …) — reach for those before writing bespoke markup.

Spec/decision record: `docs/SESSION-ORGANIZATION-PLAN.md`; grouping logic in `apps/terminal/src/features/terminal/grouping.ts`. **Bugfix (2026-08-04):** in multi-server mode (`components/session-list.tsx`), the org header inside a server's subtree reused the same zero-indent styling as root-level org headers, so it sat flush with its parent Server row instead of nesting under it — Project/Session rows stepped in further but the Server→Org step was missing. Fixed with a shared `indentClass(level)` helper: org/project/session rows now compute their depth from whether they're rendered inside a per-server subtree (`serverId` set bumps every level by one), giving a consistent ~1rem step per level (Server 0 → Org 1 → Project 2 → Session 3). Single-server mode's indentation (levels 0/1/2, unchanged classes) is untouched.

**Dead session persistence** (new): when a reachable server's `tmux list-sessions` output no longer includes a metadata-tracked session (e.g. host rebooted, session manually killed outside the gateway), the session is NOT pruned from the metadata sidecar. It appears in `GET /api/sessions` with `alive:false, reachable:true` — a "dead" placeholder, rendered dimmed with "session ended" status. Delete is enabled (metadata-only cleanup, no `kill-session` call); Mute is disabled (nothing to mute); Rename/Move stays enabled (metadata-only). A "Reconnect" action creates a replacement session pre-filled from the dead session's name/org/project (cwd is NOT persisted anywhere today, so it falls back to the server's default — a known follow-up would persist cwd at create time). Dead rows have no TTL — intentional, they persist until explicit user deletion. This reverses the prior auto-pruning behavior of `metadata.pruneToExisting()` for reachable servers, which is now removed from the reachable-server code path.

**Connected Servers — multi-server MVP** (2026-07-15): Option C from `docs/MULTI-SERVER-PLAN.md` (SSH + remote tmux) is now implemented. The gateway routes all tmux work through a single exec seam (`serverExecArgv`) that either runs tmux locally (for the implicit `local` server) or via `ssh -tt … tmux …` for registered remote servers. SSH multiplexing (`ControlMaster`/`ControlPath`/`ControlPersist=60s`) keeps attach latency low by reusing one TCP+auth handshake per server. **CLI turn-finished hook notifications** (2026-08-04): closes a gap in the "Job finished" push feature above — the shell-transition poll loop stays silent for an entire interactive `claude`/`codex` CLI session (the pane's foreground command never returns to a shell between turns). Adds a SECOND, independent signal source feeding the SAME push pipeline (`push.js`/`sendToAll()`, VAPID, the SW — none of that changes): Claude Code's `Stop`/`Notification` hooks and Codex's `[[hooks.Stop]]` (preferred; stdin JSON) or legacy `notify` (argv-based fallback) invoke `apps/terminal-gateway/scripts/hook-notify.sh`, which POSTs `/api/push/hook-notify`. Auth is a **dedicated** `HOOK_NOTIFY_TOKEN` (`pnpm --filter @sparklab/terminal-gateway generate-hook-token`) — deliberately separate from `GATEWAY_API_TOKEN`/`KANBAN_API_TOKEN` since a hook config lives on every machine a user runs claude/codex from and fires every turn, a less-trusted exposure than a manually-invoked MCP client; checked by its own `isHookNotifyAuthorized` predicate, scoped to exactly this one route. Session identity resolves from the bare tmux name (`tmux display-message -p -t "$TMUX_PANE" '#{session_name}'`) against the metadata sidecar, but **fails closed on staleness**: dead-session metadata persists indefinitely (see "Dead session persistence" above), so the gateway confirms **liveness** with a targeted `tmux has-session` per candidate and requires exactly one live match (zero or more-than-one → `unknown_session`/`ambiguous_session`, never a guess). Respects the per-session `muted` flag but **ignores** `minDurationMs`/`notifyOnStart` (those encode shell-job-_duration_ semantics that fight per-turn granularity). Idempotent (dedupes by caller-supplied `eventId` — a turn/prompt id — for 10 min; a short cooldown fallback when absent) and rate-limited (20/session/min). The gateway only ever emits **fixed template copy** ("Claude finished" / "Codex finished" / "Claude needs input") **plus the session's own name and org/project** (user-assigned labels already shown in the sidebar, pulled from the same metadata that gates `muted` — e.g. "Claude finished responding — my-session (work/backend)") so notifications for different sessions are distinguishable; a caller-supplied `detail` field is logged (capped, observability-only) but never echoed into the push payload, specifically because Codex's legacy `notify` payload can carry real prompt/response text as its own argv (a `ps`-visible exposure the script cannot retroactively hide — documented as a known reduced-privacy fallback; `hooks.Stop`'s stdin delivery is preferred and does not have this exposure). The script always exits 0 and never writes stdout (required so it can never block a Claude `Stop` or interfere with Codex), and never puts the bearer token on any process's argv (curl's `-K` reads the `Authorization` header from a process substitution, not `-H`). Tested by `apps/terminal-gateway/test/hook-notify-endpoints.js` (`test:hook-notify`, 13 checks incl. auth, validation, the fail-closed dead-session liveness check, mute suppression, duration-threshold bypass, idempotency, rate limiting, a leak-guard regression proving `detail` never changes the encrypted push payload's ciphertext length, and its positive counterpart proving session name/org/project DO) + manual end-to-end verification of all four script modes, deployed and fired live against `prod-gateway`. **Bugfix (2026-08-04):** the initial rollout's `~/.claude/settings.json` hook `command` used `~/...` — Claude Code's hook runner does not expand `~` (unlike an interactive shell), so the command failed with ENOENT and the hook silently never fired; Codex's `config.toml` already used an absolute path and was unaffected. Found by temporarily instrumenting the _installed_ script (normally silent-by-design) and driving REAL `claude`/`codex` turns end to end (a fake piped JSON payload — the only verification method used pre-rollout — proves the gateway route and script logic but never proves the CLI actually invokes the script). Fixed to an absolute path; also note a long-running interactive session only reads hook config at its own startup, so an already-open session needs an exit+relaunch to pick up any hook-config change. Full design record (including the two-round external review that shaped D1–D6, the fail-closed session resolution, and this postmortem): `docs/HOOK-NOTIFICATIONS-SETUP.md`. **Munder Difflin viewer — gateway-proxied VNC, fourth pluggable artifact** (2026-08-16): a live view of a **separate** app — Munder Difflin (`~/workspaces/sparklab/munder-difflin`, its own Electron desktop app, not part of this repo) — run headless on this same host under Xvfb and exposed as `components/munder-difflin-dialog.tsx` (sandboxed iframe host, `allow-scripts allow-same-origin allow-forms allow-modals`) + the self-contained `apps/terminal/public/munder-difflin/app.html`, opened by an always-enabled header button (`AppWindow` icon), `munderDifflinOpen` store slice, and `?munder-difflin` URL flag — same pattern as Kanban/PM/Agentic. Munder Difflin's headless display is driven via its own `run-desktop` skill (`xvfb-run` + a Playwright driver over tmux session `md`) and bridged out with `x11vnc` (RFB on TCP `:5900`, loopback-only) + `websockify --web /usr/share/novnc` (noVNC's static client + WS-to-TCP bridge, also loopback-only on `:6080`) — none of that is managed by this repo, it's an ad-hoc process the operator starts by hand. **The gateway is the only thing between the browser and that bridge**: `GET /api/munder-difflin/*` (`proxyMunderDifflinHttp`) reverse-proxies noVNC's static client + `vnc.html` from `127.0.0.1:6080`, and a WS-upgrade handler at `/api/munder-difflin/websockify` (`proxyMunderDifflinUpgrade`) raw-socket-relays to the same target (`MUNDER_DIFFLIN_VNC_TARGET`, env-configurable, default `127.0.0.1:6080`) — gated by the same cookie auth/origin allowlist as every other `/api/*` route, since the bridge itself has none. This is deliberate: a hardcoded `host:6080` iframe src would be unreachable over the loclx tunnel (only the single proxied origin is tunneled) and would leave an unauthenticated port reachable on the LAN; routing through the gateway fixes both. **Two intermediate designs were built, fully verified, then deliberately reverted (by request) back to this noVNC+websockify baseline** — via `git revert`, not history rewrite, so both stay intact and buildable from their own commits if ever revisited: (1) dropping just `websockify` and having the gateway speak WS-to-TCP directly to x11vnc's RFB port itself (`net.connect`, no protocol awareness needed — websockify's TCP-bridging half is generic); (2) further replacing noVNC's client entirely with a from-scratch RFB (RFC 6143) implementation in `app.html` (handshake, a `SetPixelFormat` byte order chosen to drop straight into Canvas `ImageData`, Raw+CopyRect-only `SetEncodings`, PointerEvent/KeyEvent encoding with a Unicode-keysym fallback) — proving the gateway's WS endpoint is genuinely protocol-agnostic either way. **Known environment fix (2026-08-16, ad-hoc/operational, not code):** Munder Difflin's default window (`1440x900`) was wider than the original `1280x1024` Xvfb screen, clipping the right edge of its UI out of the visible/VNC'd area — fixed by relaunching Xvfb at `1920x1080`; this is **not persisted** across a host reboot or the `md` tmux session dying, and needs redoing by hand if that happens. The dialog is deliberately sized `h-[95vh]`/`max-w-[95vw]` (near-fullscreen) rather than the other artifacts' shared `h-[85vh] sm:max-w-6xl` reading-width cap, since this is a live desktop view, not text/form content — note both a base and an explicit `sm:`-prefixed `max-w-[95vw]` are required (Tailwind's responsive variants don't get deduped against an unprefixed override by `twMerge`, so `DialogContent`'s default `sm:max-w-lg` silently wins at desktop widths otherwise). No automated tests exist for this feature (manual browser verification only, each time, including a raw RFB-banner-over-WS check and a live click+type+submit round-trip against the running app, for the two reverted designs).

**Notes — OneNote-style pluggable HTML artifact** (2026-08-28): a gateway-owned Notebooks → Sections → Pages (+ subpages) note-taking tool, structurally a sibling of Kanban/PM but with a **deliberately different store shape** (`docs/NOTES-TOOL-PLAN.md` D2): `src/notes.js` splits state into a small `data/notes.json` **tree** (notebooks/sections/page metadata + the ordering arrays, rewritten whole like `kanban.js`) and **one `.md` file per page body** under `data/notes-pages/<pageId>.md` — a debounced-autosave page body never re-serializes the whole store. Write-ordering is asymmetric by design: create/delete fail toward an orphan body file (swept by `load()`); a body **update bumps `page.rev` in the tree BEFORE writing the body**, so a crash mid-write fails toward a false conflict, never a silently-accepted stale write. **Two-tier `rev`** (D3): `page.rev` (title/body only) and `notebook.rev` (structural — section/page add/move/delete) are independent, so an agent appending to a page never 409s a human reordering sections. `Section.pageIds[]` is the sole flat order authority (D5, mirrors Kanban's `Column.cardIds[]`); `parentId` is a pure containment/indent edge for subpages (cycle-checked like `pm.js`), and `movePage` relocates a page's **whole subtree as one contiguous run**. A **body-PATCH 409 is surfaced, never auto-retried** (D4) — unlike Kanban's `move`, a page-body PATCH is a blind overwrite, so replaying it would silently discard a concurrent write; the artifact instead shows a non-destructive "this page changed elsewhere" banner with explicit Reload (primary) / "Overwrite — discards the other change" actions. `GET/POST/PATCH/DELETE /api/notes/*` in `server.js` (`handleNotes`) follow the same coded-error→HTTP mapping as Kanban/PM and share `isArtifactBearerAuthorized`; Notes also joined the Agentic AI Creator's MCP-target registry (`targetType: "pm"|"kanban"|"notes"`) at ship time rather than being retrofitted later. Agent tools in `tools.ts` use an **approval tiering inverted from the naive reading** (D9/D10): reads and the five additive/structural writes (`notes_create_*`, `notes_append_to_page`, `notes_move_page`) are allow-always, but the full-body-replace `notes_update_page` is coerced **one-time** (an allow-always blind overwrite could silently destroy human writing) alongside the three deletes — `notes_delete_page` exists as a one-time tool, a deliberate divergence from Kanban/PM's human-only card/task delete, mitigated by a default `orphan` (not cascade) mode and the body-file sweep leaving an accidental delete recoverable until the next `load()`. External access via `tools/notes-mcp/` (stdio JSON-RPC, mirrors `tools/kanban-mcp/`). Frontend: `notesOpen` store slice, `?notes` URL flag, always-enabled header button (lucide `NotebookText`), `components/notes-dialog.tsx` (sandboxed iframe, sized `h-[88vh]`/`max-w-[88vw]` — wider than Kanban/PM's `max-w-6xl` for the three-pane layout), self-contained `apps/terminal/public/notes/app.html` (left rail: notebooks + sections; middle: indented page tree with click-to-move, no drag in v1; right: title + Markdown textarea with a **hand-rolled rendered-subset preview** — D11, headings/bold/italic/code/lists/links/blockquote/`---`, since `react-markdown` isn't available inside a bundler-less sandboxed document; search snippets render as `textContent` only, never through the formatter).
